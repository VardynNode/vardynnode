## What's new

- **Live trading and the Binance sub-account.** Live trading uses a Binance sub-account on every paid plan. On Starter and Pro you can choose your main Binance account instead when you switch to LIVE in the dashboard (the sub-account stays the default and is recommended); Elite needs a sub-account. A trial, testnet and paper trading never need one. If your key belongs to a main account you did not choose, the bot does not start live trading and tells you in the log and on Telegram what to do.
- **The AI gives guidance only.** It writes notes for you to read; it never decides, blocks, skips or sizes a buy or a sell, and the bot trades the same with it on or off. The AI Conviction Scorer is now called AI Trade Rating and writes its rating in the log as a note. The three settings that sized trades by the AI rating are gone; Normal max trade size is the only cap.
- **A clearer start-up line when the license is not accepted.** The log now names the real reason (the license server could not be reached, the license is linked to a different server, the Binance API key changed, or the Binance account is in use by another installation) and the button to press on the dashboard's license notice. A LIVE mode returns to TESTNET until the link is reset; TESTNET and PAPER keep running.
- **Renaming a server no longer looks like a new server.** The bot keeps its identity while the system's own machine identity is unchanged; a server moved to different hardware is still treated as a new server.
- **Moving a server to the new names** now works on web-server setups that keep part of their configuration in nginx.conf or in other files under /etc/nginx; the installer never leaves a web-server configuration that fails its own test.
- **The dashboard as an app.** Every dashboard page carries the same install information. On a server with only an IP address, the installer says that a domain name is needed to add the dashboard to a phone's home screen as an app.
- **The download is named VardynNode-Setup.zip.** The same package is still published under the old name for servers whose updater asks for it; you do not need to do anything.
- **The updater command is `vn-update.sh`**: `sudo vn-update.sh --enable`, `--disable`, `--setup`, `--migrate-layout`, and the new `sudo vn-update.sh --move-names`, which tries the rename of the system folders again after a note said it could not finish. The addresses are the same: `curl -fsSL https://get.vardynnode.com/update | sudo bash` and `curl -fsSL https://get.vardynnode.com | sudo bash`. A server that already has the older command name keeps it as a link.
- **Backups end in `.vnbackup`**. A backup file from an earlier version is still accepted when you upload it.
- **System names.** On a new server the service and command are `vardynnode`; the folders are `/root/VardynNode`, `/root/vardynnode-data`, `/var/lib/vardynnode`, `/var/backups/vardynnode` and `/etc/ssl/vardynnode`; the web-server site is `vardynnode`; the update timer is `vardynnode-update.timer` and the update log is `/var/log/vn-update.log`. A server that was installed earlier is moved to these names by its next update, by itself. If that could not be finished you get one note that says nothing is broken and gives the one command to try again.
- **Optional settings are called `VN_<name>`** (the shell scripts and the few process settings); the earlier spelling is still accepted. The settings in `.env` are unchanged. The unattended premium install reads `/tmp/vn-config.yaml` (the older file name is still read).
- **A license pause that has ended but could not resume yet.** If the pause has ended and trading could not resume just now (for example the balance could not be read), the log says so in one plain line. The Resume button on the dashboard does it at once.
- **Housekeeping in the public folder.** The files carry the new names (`get-vardynnode.sh`, `vn-update.sh`, `migrate-names.sh`, `vardynnode.service`); the addresses and the commands you use are the same.
